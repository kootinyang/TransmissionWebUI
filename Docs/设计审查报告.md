# Transmission Web UI 设计审查报告

> 审查范围：`public_html/index.html` + `public_html/transmission-app.css`
> 审查维度：设计系统一致性、颜色语义、可访问性、响应式、代码质量

---

## 🔴 严重问题（建议优先修复）

### 1. 颜色变量命名与使用逻辑混乱

**现状**：`--color-*-foreground`（语义上应为"文字色"）被反向用作**背景色**，完全违背命名直觉。

| 位置 | 代码 | 问题 |
|------|------|------|
| `transmission-app.css:63` | `#toolbar-start { background-color: var(--color-info-foreground); }` | 用"前景色"做按钮背景 |
| `transmission-app.css:265` | `.leech::before { background-color: var(--color-info-foreground); }` | 进度条填充色用前景色变量 |
| `transmission-app.css:267` | `.seed::before { background-color: var(--color-success-foreground); }` | 同上 |

**影响**：维护者无法通过变量名判断正确用途，极易在后续修改中引入配色错误。

**修复建议**：
- 重命名 `--color-info-foreground` 为 `--color-info-accent` 或 `--color-info-light`
- 或新增 `--accent-info: #b2b2ff` 等语义正向的变量，用于高亮/填充场景

---

### 2. `--secondary` 与 `--border` 颜色完全相同

**现状**：
```css
:root {
  --secondary: #2e2e2e;
  --border: #2e2e2e;   /* 完全一样的值 */
}
```

Torrent 卡片的边框声明：
```css
#torrent-list .torrent {
  border: 2px solid rgba(46, 46, 46, 1);  /* = #2e2e2e */
  background-color: var(--card);           /* = #1a1a1a */
}
```

**影响**：卡片边框与 secondary 背景色完全融合，hover 前几乎不可见，卡片之间缺乏自然分隔感，界面显得"糊成一片"。

**修复建议**：将 `--border` 调亮至 `#3a3a3a` 或 `#404040`，使边框在 `#1a1a1a` 背景上可见但不突兀。

---

### 3. 选中状态文字颜色传递失效

**现状**：
```css
#torrent-list .torrent.selected {
  color: var(--white);  /* 意图：选中后文字变白 */
}
```

但子元素有更具体的选择器覆盖：
```css
#torrent-list .torrent .torrent-name {
  color: var(--foreground);  /* #ffffff，与 --white 相同但优先级更高 */
}
#torrent-list .torrent .torrent-labels {
  color: var(--muted-foreground);  /* 不会被父级 color 覆盖 */
}
```

**影响**：`.selected { color: var(--white) }` 实际上只影响到极少数没有显式声明颜色的元素，选中后文字并未真正统一变色，设计意图落空。

**修复建议**：显式覆盖选中状态下子元素的颜色：
```css
#torrent-list .torrent.selected .torrent-name,
#torrent-list .torrent.selected .torrent-labels,
#torrent-list .torrent.selected .torrent-progress-details {
  color: var(--white);
}
```

---

### 4. SVG 中大量硬编码颜色

**现状**：状态图标、Inspector 图标、菜单图标等的 SVG `stroke`/`fill` 均写死色值：

```css
/* 进度条状态图标 */
stroke='%23B2B2FF'   /* leech */
stroke='%23B6FFCE'   /* seed */
stroke='%23b8b9b6'   /* paused */
stroke='%23ff8400'   /* verify/magnet */
stroke='%23ff5c33'   /* error */

/* Inspector 卡片图标 */
stroke='%23111111'   /* 所有 inspector-card-icon */
```

**影响**：如果将来支持 light mode 或主题切换，这些图标颜色不会跟随变化，会出现深色图标在深色背景上看不见的问题。

**修复建议**：
- 将 SVG 中的 `stroke="..."` 改为 `stroke="currentColor"`
- 通过父元素的 `color` 属性控制图标颜色
- 或改用 CSS mask-image + background-color 的组合（项目中已有此模式，应统一推广）

## 🟡 中等问题（建议修复）

### 5. 缺少 Focus 可见样式（可访问性缺陷）

**现状**：工具栏按钮、torrent 卡片、右键菜单项、overflow 菜单项等**均只定义了 `:hover`，没有 `:focus-visible`**。

**影响**：键盘导航用户完全无法感知当前焦点位置，不符合 WCAG 2.1 的可访问性要求。

**修复建议**：为所有交互元素补充焦点环：
```css
.toolbar-button:focus-visible,
#torrent-list .torrent:focus-visible,
.menu-item > button:focus-visible {
  outline: 2px solid var(--primary);
  outline-offset: 2px;
}
```

---

### 6. 暗色主题对比度隐患

**现状**：部分颜色组合的对比度处于临界值：

| 组合 | 对比度 | WCAG AA |
|------|--------|---------|
| `#b8b9b6` on `#1a1a1a` | ~5.8:1 | 达标（刚好） |
| `#b8b9b6` on `#222229` | ~4.8:1 | 不达标 |
| `#ff8400` on `#1a1a1a` | ~7.5:1 | 达标 |
| `#b2b2ff` on `#222229` | ~4.9:1 | 不达标 |

**影响**：info 状态（`--color-info: #222229`）上的文字 `--color-info-foreground: #b2b2ff` 对比度仅约 4.9:1，对于视力较弱或屏幕亮度较低的用户可能难以辨认。

**修复建议**：将 `--color-info` 调亮至 `#2a2a3a` 或 `--color-info-foreground` 调亮至 `#c4c4ff`，确保对比度 ≥ 7:1（AAA 级）。

---

### 7. 响应式断点跳跃过大

**现状**：
```css
@media(width < 600px) { ... }
@media (max-width: 768px) { ... }
@media (width >= 600px) { ... }
@media (width >= 950px) { ... }
```

- 600px 以下：Inspector 变为全屏覆盖
- 600px-768px：Inspector 仍为 450px 固定宽度
- 768px：padding 等微调
- 950px 以上：Inspector 融入文档流

**影响**：600px-768px 区间内，Inspector 固定 450px 宽度会严重挤压主内容区（仅剩 150-318px），布局显得拥挤。

**修复建议**：增加中间态断点，如 `@media (max-width: 900px)` 时缩小 Inspector 至 320px，或 `@media (max-width: 750px)` 时提前切换到全屏覆盖模式。

---

### 8. 声明了 `color-scheme: light dark` 但无 Light 主题

**现状**：`:root` 中声明了 `color-scheme: light dark`，但**只有一套暗色变量**，没有 light mode 的变量定义。

**影响**：当用户系统为 light mode 时，系统级控件（如滚动条、`<select>` 下拉框、复选框）会呈现浅色，与页面暗色风格冲突。

**修复建议**：二选一：
- **方案 A**：移除 `color-scheme: light dark`，明确声明为仅暗色主题
- **方案 B**：补充 `@media (prefers-color-scheme: light)` 下的完整变量定义

## 🟢 轻微问题（可选优化）

### 9. 代码冗余

**现状**：多处 `mask-image` 被重复声明两次：
```css
.file-priority-radiobox>*.low:after {
  mask-image: var(--image-chevron-dn);
  mask-image: var(--image-chevron-dn);  /* 重复行 */
}
```

**修复建议**：删除重复声明。

---

### 10. 选择器过深过具体

**现状**：大量使用 `#id > .class > element` 的深层选择器链：
```css
#torrent-list .torrent .torrent-name { ... }
#torrent-list .torrent .torrent-labels { ... }
#torrent-list .torrent .torrent-progress-details { ... }
```

**影响**：
- CSS 特异性战争，后续覆盖困难
- 必须严格保持 DOM 结构不变，否则样式失效
- 维护成本高

**修复建议**：长远来看，可采用 BEM 命名规范（如 `.torrent-card__name`、`.torrent-card__labels`），或使用更扁平的选择器结构。
